# glory-booking

ระบบจองคิวไลฟ์ GLORY VITAL (Mc จองคิว, Admin เสริมรับคิว, เจ้าของดูสรุปรายเดือน)
ย้ายจาก HTML + Apps Script + Google Sheet มาเป็น **Next.js + Tailwind + Supabase** รันด้วย **bun**

## โครงสร้าง

| ส่วน | ไฟล์ |
| --- | --- |
| หน้าเว็บ | `src/app/page.tsx`, `src/components/*` |
| API (แทน `doPost` เดิม) | `src/app/api/{slots,book,cancel,my,owner}/route.ts` |
| กฎการจอง / รับคิว / ยกเลิก (atomic, ล็อกกันจองชน) | `supabase/migrations/*_init.sql` (ฟังก์ชัน `book_mc_slots`, `assign_admin_slots`, `cancel_slot`) |
| ลงปฏิทิน Google | `src/lib/calendar.ts` + `src/app/api/cron/calendar/route.ts` |
| นำเข้าข้อมูลจากชีตเดิม | `scripts/import-sheet.ts` |
| หน้าเว็บเดิม (อ้างอิง) | `legacy/index.html` |

## ตั้งค่าครั้งแรก

1. **Supabase**: สร้างโปรเจกต์ที่ supabase.com
   - คัดลอก `.env.example` เป็น `.env.local` แล้วใส่ URL / anon key / service role key
   - สร้างตาราง: `bun x supabase login` → `bun x supabase link` → `bun run db:push`
     (หรือวางไฟล์ใน `supabase/migrations/` ลงใน SQL Editor แล้วกด Run)
   - Authentication > Providers > **Google**: เปิดใช้ ใส่ Client ID / Secret จาก Google Cloud
   - Authentication > URL Configuration: ใส่ Site URL และเพิ่ม `http://localhost:3000/auth/callback`
2. **Google Cloud**: สร้าง Service Account เปิด Calendar API + Sheets API ใส่อีเมล/คีย์ใน `.env.local`
   - แชร์ชีต LIVE GLORY 2026 ให้อีเมล Service Account (ผู้มีสิทธิ์อ่าน)
   - Mc / Admin ทุกคนแชร์ปฏิทินของตัวเองให้อีเมล Service Account สิทธิ์ "ทำการเปลี่ยนแปลงกิจกรรม"
3. **นำเข้าข้อมูล**: `bun run import:sheet --dry-run` ดูสรุปก่อน แล้ว `bun run import:sheet`
4. **รัน**: `bun install` → `bun dev` แล้วเปิด http://localhost:3000

- ไลฟ์ครั้งเดียวคลุมหลาย slot: ติ๊กหลาย slot (แพลตฟอร์มเดียวกัน) แล้วแนบรูปเดียว
- ข้อมูล: ตาราง `live_proofs` + `live_proof_slots` (slot ของ Mc ละ 1 หลักฐาน) / รูปอยู่ใน Storage bucket `live-proofs` (ส่วนตัว)

- ตารางสรุปกดหัวคอลัมน์เพื่อเรียง (มากไปน้อย / น้อยไปมาก / ลำดับเดิม)

  ไลฟ์วันนี้ (สถานะ + หลักฐาน/GMV) · slot ที่ยังไม่มี Mc / Admin ใน 7 วันข้างหน้า · หลักฐานและ GMV ที่ค้าง 7 วันล่าสุด

  · มุมมอง Mc / Admin (หน้าจองแบบดูอย่างเดียว) — Owner ที่มีหน้าเจ้าของจึงไม่มี "Plan Slot Live" / "Booking (ดูอย่างเดียว)" ในเมนูหน้าแล้ว
  (Owner ที่มีแค่สิทธิ์ Plan Slot Live ยังเปิดเป็นหน้าแยกได้เหมือนเดิม)

## ซิงค์สองทางกับ Google Sheet

แก้ slot ได้ทั้งในชีต (แท็บ "ลงตาราง Deal Mc" / "ลงตาราง Admin เสริม") และในเว็บ (หน้าเจ้าของ > จัดการ slot)

- **ชีต -> เว็บ**: `apps-script/web-sync.gs` ในสคริปต์ที่ผูกกับชีต ส่งเลขแถวที่ถูกแก้ไป `/api/sync/sheet`
  (Script Property `SYNC_SECRET` = `SHEET_SYNC_SECRET`) เว็บอัปเดตเฉพาะคอลัมน์ที่ถูกแก้
- **เว็บ -> ชีต**: DB trigger จดงานใน `sheet_jobs` แล้ว `src/lib/sheet-sync.ts` เขียนลงชีต
  slot ใหม่แทรกในกลุ่มวันเดียวกัน เรียงตามเวลาเริ่ม
- คอลัมน์ **V** = รหัส slot (ระบบเขียนเอง ห้ามแก้) ใช้จับคู่แถว จึงแทรก/เรียงแถวในชีตได้
- **ลบแถวในชีต = ลบ slot ในเว็บ** (เฉพาะ slot ตั้งแต่วันนี้ ลบ event ในปฏิทินให้ด้วย) ผ่าน trigger `onChangeToWeb`
  (อัปเดต `web-sync.gs` แล้วต้องกด Run `setupWebSync` อีกครั้ง) ล้างข้อมูลทั้งแถว (แพลตฟอร์ม/วัน/เวลาว่าง) ก็นับเป็นลบ
  - ถ้า slot หายจากชีตเกินครึ่งในครั้งเดียว (> 20 slot) ระบบไม่ลบให้ กันคอลัมน์ V ถูกล้างโดยไม่ตั้งใจ
  - slot ที่ถูกลบแถวในชีตแล้ว เว็บจะไม่เขียนแถวกลับลงชีตอีก
  - ลบแถวแล้วกด Undo: แก้ช่องใดก็ได้ในแถวนั้น ระบบจะสร้าง slot ใหม่ให้
  - ยกเลิกคิวโดยไม่ลบ slot = ลบชื่อ หรือสถานะ "แคน" / ลบ slot ในเว็บจะลบแถวในชีตด้วย
- **แถวคู่ Mc <-> Admin** (ไลฟ์เดียวกัน = แพลตฟอร์ม + วัน + เวลาเดียวกัน)
  - พิมพ์แถวใหม่ในแท็บหนึ่ง (ตั้งแต่วันนี้) ระบบสร้างแถวคู่ในอีกแท็บให้ (แท็บ Admin ใส่หมายเหตุ "Admin เสริม")
  - แก้แพลตฟอร์ม/วัน/เวลาในแท็บหนึ่ง แถวคู่เปลี่ยนตาม (เฉพาะเมื่อมีคู่ตัวเดียว)
  - ลบแถวในแท็บหนึ่ง = ยกเลิกไลฟ์ แถวคู่ที่ยังไม่มีคนจอง/รับหายตาม (มีคนแล้วไม่แตะ)
  - ไม่ต้องการ Admin เสริมแล้ว: ลบคำว่า "Admin เสริม" ในหมายเหตุ อย่าลบแถว
  - "ซิงค์จากชีตทั้งหมด" ไม่สร้าง/ย้ายแถวคู่ (ทำเฉพาะตอนแก้ในชีตทีละแถว)
- หน้าจอง Mc / Admin โหลด slot ใหม่อัตโนมัติทุก 15 วินาที และทันทีที่กลับมาที่แท็บ
- แก้ในชีตแล้วเว็บไม่เปลี่ยน: กด "ซิงค์จากชีตทั้งหมด" ในหน้าจัดการ slot (ตรวจแถวที่ถูกลบด้วย)
- ห้ามใช้ `bun run import:sheet` แล้ว (เขียนทับทั้งหมด สคริปต์ถูกล็อกไว้)

## สิทธิ์ของ Owner

หน้าเจ้าของ > พนักงาน > Owner > สิทธิ์ 3 ระดับต่อเรื่อง: **ไม่มี / ดูได้ / จัดการได้** (ต้องรัน SQL `20261018000000_view_only` ก่อนถึงตั้ง "ดูได้" ได้)

| เรื่อง | จัดการได้ | ดูได้ |
| --- | --- | --- |
| ฝั่ง Mc | `can_manage_mc` | `can_view_mc` |
| ฝั่ง Admin | `can_manage_admin` | `can_view_admin` |
| หลักฐานไลฟ์ (ทุก slot) | `can_manage_proofs` (หรือจัดการ Mc) | `can_view_proofs` (หรือดู Mc) |
| Plan Slot Live | `can_plan_slots` | `can_view_plan` |
| Data analytics | `can_view_analytics` | `can_view_analytics` + `analytics_readonly` |

- จัดการ Mc = สรุปรายเดือน (+ ส่งออก) / ตาราง slot / รายชื่อ / กฎ เห็นและแก้ได้เฉพาะฝั่ง Mc (Admin กลับกัน)
- จัดการได้ทั้ง Mc + Admin = ทั้งหมด รวมถึงรายชื่อและสิทธิ์ของ Owner คนอื่น / แก้สิทธิ์ตัวเองไม่ได้
- **ดูได้** = เห็นข้อมูลและส่งออกได้ แต่ไม่มีปุ่มแก้ และ**ไม่เห็นค่าจ้าง** (ค่าจ้าง/ชม. ยอดเงิน Commit — server ไม่ส่งมาเลย ดู `payHidden` ใน `/api/owner`)
  เห็นชั่วโมง ผลงาน GMV เบอร์ อีเมล ได้ตามปกติ · Plan ดูได้ = เห็นแพลน + สรุปชั่วโมง ติ๊ก/บันทึกไม่ได้ · Data analytics ดูได้ = ไม่มีแท็บอัปโหลด แก้แคมเปญไม่ได้
- Owner ใหม่ค่าเริ่มต้น: จัดการ Mc + Admin ได้ เรื่องอื่นไม่มี
- ฝั่ง server: `src/lib/auth.ts` คิด `owner.mc/admin/proofs/analytics/plan` = จัดการได้ และ `owner.see.*` = ดูได้หรือจัดการได้
  API ที่อ่านอย่างเดียว (GET) ใช้ `requireOwner(…, "read")` / `requireAnalytics(…, "read")` / `requirePlanner(…, "read")` ที่เหลือ (แก้ไข) ต้องจัดการได้
- ตาราง slot > มุมมอง Mc / Admin = หน้าจองที่ Mc / Admin เห็น (ดูอย่างเดียว จองแทนไม่ได้)

## ค่าจ้าง / หักเงินมาสาย

- ค่าจ้างต่อชั่วโมง: `staff.hourly_rate` (รายคน) ไม่ตั้ง = `settings.default_mc_rate` / `default_admin_rate`
- Commit แบบขั้นรายคน (`staff.commit_tiers` ตั้งในหน้าพนักงาน) เช่น ค่าจ้างปกติ 1,000 / 10+ ชม. 950 / 21+ ชม. 900 / 41+ ชม. 850
  เดือนไหนจอง (ไม่นับคิวที่ยกเลิก) ถึงขั้นไหน ทุกชั่วโมงของเดือนนั้นคิดราคาขั้นนั้น (`monthRate` ใน `src/lib/pay.ts`)
  (`commit_hours` / `commit_rate` เป็นคอลัมน์เก่า ไม่ใช้แล้ว)
- ยอดเงินต่อ slot = ชั่วโมง x ค่าจ้าง/ชม. ของเดือน x (1 - ส่วนที่หักมาสาย) ไม่นับคิวที่ยกเลิก
- ช่อง "ยกเลิก" ในสรุปรายเดือน = "แคน" ในชีต (`is_cancelled`) + กดยกเลิกผ่านเว็บ
  (กดยกเลิกผ่านเว็บ `cancel_slot` เอาชื่อออกจาก slot ให้คนอื่นจองต่อ จึงอ่านจากประวัติ `booking_logs` แทน — `webCancels` ใน `src/lib/data.ts`
  นับ 1 ครั้งต่อคนต่อ slot · จองกลับมาแล้ว / ลบรายชื่อออกไปแล้ว = ไม่นับ) กดที่ชื่อเพื่อดูว่ายกเลิกคิวไหน เมื่อไร ก่อนไลฟ์กี่วัน
- กฎมาสาย `src/lib/pay.ts` (หน้ากฎการทำงานใช้ตัวเดียวกัน): ไม่เกิน 5 นาที ไม่หัก / 5–30 นาที 30% / 30–60 นาที 50% / เกิน 1 ชม. 100%
- บันทึกเวลาสายในชีต: Mc = แท็บ Deal Mc คอลัมน์ **L** (Remark) / Admin = แท็บ Admin เสริม คอลัมน์ **M**
  - เขียนได้แบบ `15`, `15 นาที`, `สาย 15`, `สาย 15 นาที`, `มาช้า 15 นาที`, `สาย 1 ชม.` ข้อความอื่น = ไม่หัก
- ไลฟ์ชดเชย (ไลฟ์ต่อแทนคนถัดไปที่มาสาย): ช่องเดียวกับเวลาสาย ใส่ `ชดเชย 10` หรือ `+10` (= 10 นาที) เก็บใน `bonus_minutes`
  (Mc = แท็บ Deal Mc คอลัมน์ L / Admin = แท็บ Admin เสริม คอลัมน์ M)
  - ⚠️ `+10` ใช้ได้เฉพาะเมื่อตั้งคอลัมน์เป็น "ข้อความธรรมดา" ไม่งั้น Google Sheets แปลงเป็นเลข 10 (= สาย 10 นาที)
  - เทียร์ (`BONUS_TIERS`): 5–15 นาที = ¼ ชม. / 16–30 นาที = ½ ชม. / 31–60 นาที = 1 ชม. / ต่ำกว่า 5 นาที = 0
  - เกิน 60 นาที = ชั่วโมงเต็ม + เศษคิดตามเทียร์ / ใช้ค่าจ้าง/ชม. ของเดือนนั้น / ไม่โดนหักมาสาย / ไม่นับเป็นชั่วโมง Commit
  - เช่น 700 บาท/ชม.: `+10` = 175, `+20` = 350, `+45` = 700, `+75` = 875
  - หน้ากฎการทำงานแสดงตัวเลขบาทตามค่าจ้างของแต่ละคน
- Mc / Admin เห็นยอดของตัวเองใน "ตารางของฉัน" เจ้าของเห็นใน "สรุปรายเดือน" (+ ส่งออก)

## ส่งออกข้อมูล (Excel / Google Sheet)

ปุ่ม "ส่งออก" ทุกปุ่มมีดรอปดาวน์ให้เลือก (`src/components/ExportMenu.tsx`)
- **Microsoft Excel**: สร้างไฟล์ .xlsx ในเบราว์เซอร์ (`src/lib/export.ts`) ตัวเลขเป็นตัวเลขจริง ลิงก์กดได้ หัวตารางตรึงไว้
- **Google Sheet**: `/api/export/sheet` สร้างชีตใหม่ในไดรฟ์ของบัญชีระบบ แชร์สิทธิ์แก้ไขให้อีเมลของคนที่กด (ไม่ส่งอีเมลแจ้ง) แล้วเปิดในแท็บใหม่ — หาไฟล์ย้อนหลังได้ใน "แชร์กับฉัน"
- หน้าเจ้าของ > สรุปรายเดือน: ใบสรุปค่าจ้างรายคน / รายคน-รายวัน / สรุป / รายละเอียด
- หน้าสถิติไลฟ์: ภาพรวมรายเดือน, ทั้งปี, เทียบช่วง (MoM / QoQ / YoY), แคมเปญ (Campaign on Campaign) — ตามตัวกรองที่เลือกอยู่ (`src/lib/live-export.ts`)
- ปุ่ม "สไลด์" (เทียบช่วง / แคมเปญ): PowerPoint (.pptx สร้างในเบราว์เซอร์ `src/lib/live-slides.ts`) หรือ Google Slides (`/api/export/slides` แปลงไฟล์เดียวกัน)
  10 หน้า: ปก · ตัวเลขหลัก · ทุกตัวชี้วัด · อะไรทำให้ GMV เปลี่ยน (ชั่วโมงไลฟ์ vs ยอดต่อชั่วโมง + กรวยการขาย) · กราฟแยกบัญชี · กราฟตามเวลา · ตารางบัญชี · Top 5 ไลฟ์ · วิเคราะห์และข้อเสนอแนะ · สรุป
  การวิเคราะห์ (`src/lib/live-insights.ts`) ใช้กฎจากตัวเลขจริง นับเฉพาะที่เปลี่ยนเกิน 5% ข้อเสนอแนะผูกกับสาเหตุที่พบ
